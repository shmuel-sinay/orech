## מה אני רוצה
1. להחזיר את המכשיר לפעולה ולקרוא את יומני האשף (logcat) כדי להבין למה הוא נתקע. ייתכן שזו אחת מהחבילות או ההגדרות שאנחנו שינינו.
2. לשקול להחליף את האשף של גוגל באפליקציית ההפעלה שלנו (בחירת גרסה), כך שתעלה מיד אחרי איפוס וצריבה ותשתלט על ההגדרה. הרעיון: אפליקציה עם אותו שם חבילה `com.google.android.setupwizard` ובאותו מיקום (`/system/system_ext/priv-app/SetupWizard/SetupWizard.apk`), חתומה במפתח הפלטפורמה שלנו. אי אפשר לחתום בחתימה זהה לגוגל (אין לנו את המפתח), אבל אחרי איפוס אין התנגשות חתימות. היא צריכה: להגדיר שפה ושעה (או להשאיר ברירת מחדל), להציג את בחירת הגרסה עם PIN, להגדיר בסוף את `user_setup_complete=1` ו-`device_provisioned=1` ולהשבית את עצמה. הפקודות שבעבר הספיקו כשהסרתי את האשף: `settings put secure user_setup_complete 1` ו-`settings put global device_provisioned 1` (`disable_window_blurs 1` הוא קוסמטי, לא חובה).
3. **שמירה על נעילה:** האפליקציה חייבת לבדוק דגל קבוע ב-`/mnt/vendor/protect_s/orech/` (שורד איפוס) ולא להציג את בחירת הגרסה אם כבר נבחרה, אחרת לקוח יכול לאפס ולבחור "פתוחה".
4. לפני שמשביתים או מחליפים את האשף: לבדוק ש-PackageManager לא דורש אותו (בדוק בקוד/בלוג, בדיוק כמו בקריסה של `sdksandbox`, שגרמה ל-recovery). לא להחליף בלי לבדוק, ולא בלי גיבוי של הקובץ המקורי.

## פתוח מהפעם הקודמת (לא חייב לעשות עכשיו)
משדר ה-GPS המובנה ("מיקום ב-USB" בהגדרות > מערכת) נבדק רק בסימולציה, ולא מול משדר u-blox אמיתי. הבקרה במכשיר במצב בדיקות (`noenforce` קיים ב-`protect_s`), ולכן לא תכבה אותו. כל שינוי בקבצים המנוטרים מחייב `approve` (ראה HANDOFF).
